# Интернет-магазин на Django REST Framework

REST API учебного интернет-магазина. Пользователи регистрируются, просматривают каталог, управляют личной корзиной и оформляют заказы. При оформлении заказа сервер одной транзакцией проверяет баланс и остатки, сохраняет состав заказа, списывает средства и товары, затем очищает корзину.

## Стек

- Python 3.12
- Django 5.2 LTS
- Django REST Framework
- PostgreSQL
- JWT-аутентификация
- drf-spectacular и Swagger UI
- Docker Compose

## Запуск через Docker Compose

1. Для локальной разработки настройки из `.env` уже включены в репозиторий. При необходимости создайте собственные значения в окружении или файле `.env.private` и запустите Compose с `--env-file .env.private`.

   ```bash
   docker compose up --build
   ```

Если `SECRET_KEY` не задан, контейнер создаёт временный ключ при запуске. После пересоздания контейнера ранее выданные JWT перестанут работать. Для постоянного окружения задайте собственный `SECRET_KEY` и `POSTGRES_PASSWORD` через переменные окружения или приватный файл.

При запуске контейнер применяет миграции. API доступно по адресу `http://localhost:8000/api/`, Swagger UI - `http://localhost:8000/api/docs/`, Django Admin - `http://localhost:8000/admin/`.

Создайте администратора в отдельном терминале:

```bash
docker compose exec web python manage.py createsuperuser
```

Останавливайте контейнеры командой `docker compose down`. Данные PostgreSQL сохраняются в Docker volume `postgres_data`.

## Локальный запуск

Нужны Python 3.12+ и доступный PostgreSQL. После создания виртуального окружения:

```bash
pip install -r requirements.txt
```

Для локального запуска задайте `DATABASE_URL` для PostgreSQL на `localhost` и собственный `SECRET_KEY` в окружении. Затем выполните:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

## Аутентификация

Зарегистрируйте пользователя через `POST /api/auth/register/`, затем получите пару JWT через `POST /api/auth/token/`:

```json
{
  "username": "customer",
  "password": "your-password"
}
```

Передавайте access-токен в заголовке `Authorization: Bearer <access>`. Срок жизни access-токена - 30 минут, refresh-токена - 7 дней. Обновление выполняется через `POST /api/auth/token/refresh/`.

## API

Все маршруты ниже имеют префикс `/api`. Для всех маршрутов, кроме регистрации, получения токена и публичного каталога, нужен JWT.

| Метод | Путь | Назначение | Доступ |
| --- | --- | --- | --- |
| `POST` | `/auth/register/` | Регистрация | Публичный |
| `POST` | `/auth/token/` | Получить JWT | Публичный |
| `POST` | `/auth/token/refresh/` | Обновить JWT | Публичный |
| `GET` | `/users/me/` | Профиль и баланс | Пользователь |
| `POST` | `/users/me/top-up/` | Демо-пополнение своего баланса | Пользователь |
| `GET` | `/products/` | Список товаров | Публичный |
| `GET` | `/products/{id}/` | Карточка товара | Публичный |
| `POST`, `PUT`, `PATCH`, `DELETE` | `/products/` и `/products/{id}/` | Управление товарами | Только администратор |
| `GET` | `/cart/` | Текущая корзина | Пользователь |
| `POST` | `/cart/items/` | Добавить товар | Пользователь |
| `PATCH`, `DELETE` | `/cart/items/{id}/` | Изменить количество или удалить товар | Владелец корзины |
| `POST` | `/orders/checkout/` | Оформить заказ из корзины | Пользователь |
| `GET` | `/orders/` | Заказы текущего пользователя | Пользователь |
| `GET` | `/orders/{id}/` | Детали своего заказа | Владелец заказа |
| `GET` | `/schema/` | OpenAPI-схема | Публичный |
| `GET` | `/docs/` | Swagger UI | Публичный |

Добавление товара в корзину принимает `product_id` и `quantity`. Если товар уже есть в корзине, количество увеличивается. Изменение количества принимает `quantity`.

Пополнение баланса имитирует внесение средств и не подключено к платежному провайдеру. В рабочей системе этот маршрут нужно связать с проверяемым платежным событием, а не считать клиентский запрос фактом оплаты.

## Права доступа

- Все пользователи могут читать каталог.
- Создавать, изменять и удалять товары может только staff-пользователь.
- Каждый пользователь может читать и изменять только собственную корзину и просматривать только свои заказы.
- Django Admin предоставляет интерфейс управления товарами, пользователями и заказами.

## Тесты

Запустите тесты Django с запущенной базой PostgreSQL (или внутри контейнеров Compose):

```bash
docker compose exec web python manage.py test
```

Тесты покрывают регистрацию, профиль, демо-пополнение и предел баланса, права каталога, принадлежность корзин и заказов, проверку количества, обновление корзины, документацию API, успешное оформление, нехватку средств и товара, а также параллельное изменение корзины при оформлении заказа на PostgreSQL.
